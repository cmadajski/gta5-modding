## What the game runs found

1. The initial four-slot implementation reached valid FSR dispatches but retained most capture textures until another FSR recording used the same command list. GTA's command-list pool exposed this overly narrow retirement confirmation.
2. A second launch exposed a separate startup race: the context could exist before the polling hook was installed. The shader correctly showed a red missing-input marker and preserved the scene.
3. Loading the existing game-local provider during D3D12 device initialization fixed context tracking. A post-call native Reset hook confirmed successful recording replacement. ReShade saved an actual green-status screenshot after 120 valid technique draws, showing a spatially varying vector field over the benchmark scene. Four slots still covered only about 21% of dispatches.
4. The final build expands the lazy capture pool to 32 textures while preserving the shared 256 MiB cap, completion fences, successful-reset checks, and no-stale-input rule. Additional counters distinguish GPU work in flight, retained command recordings, unobserved submissions, and allocation failures.

## Validation scope

The Windows cross-build passes. The isolated Proton hook and ReShade FX/DXBC compiler tests pass (2/2), including normal and performance-mode shader compilation. The installer/rollback round trip and conflict checks pass against temporary fixtures.

The game screenshots establish that the real texture reaches the visualization, and the red-marker run establishes missing-input behavior. Controlled fixed-camera object motion, limb animation, wheel rotation, exact vector scale/sign calibration, switching FSR off/on, and resolution-change stress tests remain to be performed. Benchmark FPS is not an isolated measurement of overlay overhead, especially because the earlier run enabled verbose Proton logging and the verification screenshot introduces a one-time readback.
